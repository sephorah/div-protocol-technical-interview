     Contexte

     En testant l'application, trois endroits ne rendent pas ce que dessine
     uikit.png :

     1. Le bloc « lien généré » est dessiné par le kit comme une seule boîte
     contenant l'URL en
     violet monospace et l'action « Copier » en texte violet à l'intérieur.
     Aujourd'hui ce sont
     deux objets : un champ bordé au texte noir, puis un bouton à contour gris
     posé à côté.
     2. Le survol des boutons secondaires (« Copier », « Copier le code », «
     Créer une autre
     demande », « Annuler », la pagination, « Déconnexion »…) ne change que le
     fond. Le visuel attendu
     fait aussi passer le texte et la bordure au violet.
     3. Le bouton « Déposer » de l'écran client est un bouton secondaire
     (contour gris), alors que le
     kit le dessine en primaire (violet plein), à côté de « Annuler ».

     Les valeurs ci-dessous sont mesurées au pixel sur les captures de référence
     (image.png, image copy 2.png), pas estimées à l'œil :

     │ Fond de la boîte du lien      │ #F7F6FF         │ bg.subtle             │
     ├───────────────────────────────┼─────────────────┼───────────────────────┤
     │ Bordure de la boîte du lien   │ 1 px #E9E9E9    │ border                │

     ---
     1. Le survol des boutons secondaires

     Fichier : frontend/src/theme/recipes/button.ts

     La variante secondary ne définit aujourd'hui que _hover: { bg: 'bg.subtle' 
     }. Lui ajouter la
     couleur de texte et remplacer l'anneau gris par l'anneau lavande :

     _hover: {
       bg: 'bg.subtle',
       color: 'brand.fg',
       boxShadow: 'inset 0 0 0 1px var(--chakra-colors-border-accent)',
     },

     L'anneau reste un boxShadow: inset, jamais une bordure — la règle déjà
     documentée dans
     docs/architecture.md : une bordure qui apparaît au survol décale le libellé
     d'un pixel.

     Point que la demande ne couvre pas mais qu'il faut traiter dans le même 
     geste : la variante
     secondary n'a pas de bloc _disabled, contrairement à primary. La pagination
     du tableau de
     bord (dashboard-page.tsx:154 et :165) rend « Précédent » / « Suivant »
     désactivés. Sans garde, un
     bouton désactivé deviendrait violet au survol et se lirait comme cliquable.
     Ajouter, sur le modèle
     exact de primary :

     _disabled: {
       opacity: 0.5,
       _hover: {
         bg: 'bg',
         color: 'fg.muted',
         boxShadow: 'inset 0 0 0 1px var(--chakra-colors-border)',
       },
     },

     2. Le bloc « lien généré »

     Fichiers : frontend/src/components/copy-field.tsx,
     frontend/src/theme/recipes/button.ts,
     frontend/src/theme/recipes/field.ts

     Le champ reste un <Input readOnly> — ce n'est pas cosmétique : CopyField
     appelle
     inputRef.current.select() quand le presse-papier refuse (useCopy(value, 
     selectValue)), ce qui
     transforme « recopiez à la main » en un seul Ctrl+C. Remplacer l'input par
     du texte casserait ce
     repli, et le PIN comme le lien ne s'affichent qu'une fois. La boîte devient
     donc un conteneur qui
     porte la bordure, le fond et le rayon, avec un input transparent dedans.

     Structure visée dans copy-field.tsx :

     Field.Root
     ├─ Field.Label            ← conservée
     ├─ Box  (bordure 1px `border`, radius `l2`, bg `bg.subtle`, px 12px, py
     10px,
     │        display flex, align center, gap 12px, w 100%,
     │        _focusWithin → anneau `brand.solid`)
     │  ├─ Input   variant="bare"  flex=1  minW=0  textStyle="codeLink"
     textOverflow="ellipsis"
     │  └─ Button  variant="link"  flexShrink=0   → « Copier » / « Copie »
     └─ Text role="status"     ← retour de copie, inchangé

     L'anneau de focus monte sur le conteneur (_focusWithin) : laissé sur
     l'input, il dessinerait un
     second anneau à l'intérieur de la boîte.

     Deux variantes à créer dans le thème — la règle du projet est qu'un
     composant manquant se crée dans
     le thème, jamais dans la page :

     - inputRecipe, variante bare : bg: 'transparent', borderWidth: 0,
     borderColor: 'transparent', boxShadow: 'none', paddingInline: 0,
     paddingBlock: 0,
     color: 'brand.fg', et _focusVisible neutralisé (boxShadow: 'none', outline:
     'none',
     borderColor: 'transparent'). La déclarer en variante et non dans base est 
     obligatoire :
     field.ts documente déjà que la variante outline de Chakra est celle par
     défaut et bat base.
     - buttonRecipe, variante link : bg: 'transparent', color: 'brand.fg',
     fontWeight: 600,
     fontSize: '13px', paddingInline: 0, paddingBlock: 0, boxShadow: 'none',
     _hover: { textDecoration: 'underline' } — un soulignement ne prend pas de
     place, contrairement à
     un fond ou un anneau qui décaleraient le texte de l'URL à côté. Le
     _focusVisible de base lui
     donne déjà son anneau clavier. Chakra v3 n'a ni variante link sur le bouton
     ni bare sur
     l'input : pas de collision de nom.

     pnpm -C frontend theme:typegen doit être relancé après l'ajout des deux
     variantes : les unions
     ButtonVariant / InputVariant sont fermées et le tsc -b échoue sinon. Le
     script tourne déjà en
     tête de build et de lint, donc pnpm -C frontend lint suffit à le
     déclencher.

     Nommage accessible : le bouton affichera « Copier » ; lui donner
     aria-label="Copier le lien"
     pour qu'il se distingue de « Copier le code » du bloc PIN dans la même
     carte.
     copy-field.test.tsx cible getByRole('button', { name: /copier/i }), qui
     continue de le trouver.
